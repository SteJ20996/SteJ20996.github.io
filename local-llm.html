怎么跑起来 / 这个页面在测什么

整页就是一个 HTML 文件，没有构建步骤、没有后端。它直接从浏览器打 Ollama 的 HTTP 接口，所以模型、显存、算力全在你自己机器上。

  1. 装 Ollama 并拉一个模型：ollama pull qwen3:8b
  2. 让浏览器能跨域访问它（默认只允许本机进程）：
# macOS
launchctl setenv OLLAMA_ORIGINS "*" && ollama serve

# Linux（systemd）
sudo systemctl edit ollama
# 加入：
#   [Service]
#   Environment="OLLAMA_ORIGINS=*"
sudo systemctl restart ollama

# Windows（PowerShell）
setx OLLAMA_ORIGINS "*"

如果页面挂在 https:// 上而 Ollama 在 http://localhost，浏览器的混合内容策略会拦下请求。这时把本文件下载到本地用 file:// 或 http://localhost 打开即可。连不上时页面会自动落到演示模式，用一段模拟流验证界面本身。

四个指标分别是什么：

  • TTFT 首字延迟 — 从发出请求到收到第一个 token 的墙钟时间。冷启动时它主要是模型加载，热机后主要是 prompt 预填充，所以它对输入长度敏感。
  • 生成速度 — 优先用 Ollama 返回的 eval_count / eval_duration（纯解码速度，排除加载和预填充）；流式过程中先用墙钟估算。
  • 已生成 — 解码出的 token 数（eval_count）；流式过程中按 chunk 估算。
  • 模型加载 — load_duration。第二次跑同一模型时它应该接近 0；如果没有，说明模型被挤出了显存。

为什么要有预设场景：单条 prompt 测不出什么。短问候测冷启动，超长输入测预填充，长文生成测持续解码是否掉速（散热/降频），JSON 与表格测格式遵循，思维链场景测推理模型在正式作答前会烧掉多少 token。同一台机器上横向对比模型时，这几类要分开看。

测量口径的一点提醒：第一次跑一定慢，把它当加载耗时而不是推理速度；同一模型至少跑两遍取第二遍。
